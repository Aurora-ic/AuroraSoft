## Frontend architecture

Read [aurora_ui/AGENTS.md](../aurora_ui/AGENTS.md) first: this is Next.js 16, whose APIs and conventions differ from older versions — consult `node_modules/next/dist/docs/` before writing App Router code rather than relying on memory. (`aurora_ui/CLAUDE.md` just imports that file.)

Route groups map to audiences, and the group name never appears in the URL:

- `app/(educativo)/` → `/inicio`, `/estudiantes`, `/campanas`, `/documentos`, `/agenda`, `/academico`, `/casos-riesgo`, `/pruebas`, `/asentimiento`, `/configuracion` — the psychologist's app (🆕 `/inicio` and `/configuracion`, see "UI/UX: dashboard de inicio, configuración, búsqueda global..." below). `/agenda` is a hand-rolled weekly calendar grid of the logged-in psychologist's `CitaProgramada` rows (`GET /personas/citas/mi-agenda`), with reprogramar/cancelar inline per day — see "Known rough edges" below for the session that closed this (it used to be a plain text list). `/academico` is a real CRUD for `NivelEducativo`/`Grado`/`Seccion` (create/list against `GET/POST /admin/personas/academico/{niveles,grados,secciones}`), not a dashboard.
- `app/(superadmin)/master/` → AuroraSoft's own back office, guarded by `<RequireAuth rolesPermitidos={["superadmin"]}>`.
- `app/(examen)/examen/[token]/` → the student's public exam, intentionally with no sidebar and no auth guard. Keep it that way; a guard here would lock students out.

Auth is client-side only: [contexts/AuthContext.tsx](../aurora_ui/contexts/AuthContext.tsx) stores the JWT in `localStorage` under `aurora_token` and decodes `sub`/`rol`/`institucion_id` from it ([lib/jwt.ts](../aurora_ui/lib/jwt.ts)) without a `/auth/me` round-trip. **`GET /auth/me` now exists on the backend** (docs/gaps-pendientes.md) — nothing in `aurora_ui` calls it yet, so this stays the real behavior today; wiring it in would only let the UI confirm the decoded JWT against the server, not change what data is available. `<RequireAuth>` is cosmetic — the backend dependencies are the real enforcement, including the credential-versioning check above, so a token revoked by a password change fails server-side even though the frontend has no way to notice proactively.

Data fetching goes through [lib/api-client.ts](../aurora_ui/lib/api-client.ts), which attaches the bearer token and normalizes errors into `ApiError`. Login is the exception: the backend uses `OAuth2PasswordRequestForm`, so it posts `application/x-www-form-urlencoded` with the email in the `username` field.

**🆕 Un 401 ahora se maneja globalmente, en vez de por cada pantalla (hallazgo de auditoría, sesión 2026-10-16).** Antes, un 401 de cualquier endpoint (token expirado, o revocado por la verificación de versión de credencial de `core/deps.py` — ver docs/multi-tenancy-y-permisos.md) se propagaba como un `ApiError` más, y cada `page.tsx` decidía (o, en varios casos, no decidía) qué hacer con él — `AuthContext.tsx`'s `RequireAuth` solo valida el JWT localmente al montar, nunca reacciona a un 401 real a mitad de sesión. `lib/api-client.ts` no puede usar `useRouter()` directamente (no es un componente), así que ahora dispara un evento global (`window.dispatchEvent(new Event("aurora:no-autorizado"))`) en cualquier 401 antes de lanzar el `ApiError`; `AuthContext.tsx` lo escucha y llama a `cerrarSesion()` (limpia el token, limpia la sesión, redirige a `/`) — un solo lugar decide qué pasa con una sesión revocada, en vez de que cada pantalla lo maneje por su cuenta.

Tailwind v4 is configured entirely through the `@theme` block in [app/globals.css](../aurora_ui/app/globals.css) — there is no `tailwind.config`. Brand tokens: teal is the primary palette, `mist` the app background, `ink` the text, and `amber` is reserved exclusively for risk alerts. Don't spend amber on ordinary accents.

    **🆕 Autosave hardened against failed/out-of-order saves (hallazgo de auditoría, sesión 2026-10-16).** `elegirOpcion` used to update `respuestas` optimistically with no rollback on a failed `POST .../guardar` — since `faltanPreguntas` (the gate on "Finalizar") reads straight off that local state, an answer the student saw as selected but that never actually saved could sneak through to finalize undetected (the backend doesn't independently verify completeness either — see docs/gaps-pendientes.md). Three pieces close this: `confirmadoRef` tracks the last server-confirmed value per pregunta and a failed attempt rolls back to *that*, never to the optimistic value; `colaPorPreguntaRef` serializes save attempts for the *same* pregunta (never across different preguntas) so rapid option changes always reach the backend in click order, never out of order; `intentoVigentePorPreguntaRef` skips the rollback if a newer attempt for that pregunta is already queued, so a stale failure never overwrites a fresher result. Also added: up to 2 retries with backoff for a genuine network failure (not a real HTTP error response, which wouldn't change on retry), and `finalizar()` now awaits every pending save queue (button disabled meanwhile) before checking completeness, closing the window where a click on "Finalizar" lands while the last autosave is still in flight. Verified with the full Playwright suite (`npm run test:e2e`, 5/5) and `tsc --noEmit`/`next build` clean.

### Visor de archivos embebido — `components/ui/VisorArchivo.tsx`

Detecta el tipo de contenido automáticamente (PDF vs. imagen) — relevante para la evidencia del expediente clínico, que puede ser cualquiera de las dos.

Botón "Ver" agregado en los 3 lugares que antes solo tenían "Descargar": la lista "Pruebas aplicadas" de la ficha del alumno, cada versión de un documento institucional (`documentos/[id]/page.tsx`), y la evidencia del expediente clínico (`estudiantes/[personaId]/page.tsx`, ver "Evidencia" en docs/motor-documentos.md).

## 🆕 Casos en riesgo: urgencia, estado y responsable (sesión 2026-11-01)

Punto 2 del análisis de UI/UX. Las cuatro decisiones de fondo las tomó el usuario:

Se aplican a alumnos puntuales, casi siempre derivados por una preocupación, y sesgarían el promedio del grupo. Las pruebas finalizadas del mes sí las cuentan.
- **Elegibilidad antes de matricular** (`GET /educativo/pruebas/{id}/elegibilidad?persona_id=`, `crud.elegibilidad_prueba`):
